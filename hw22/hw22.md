# ⚡ Задачи по синхронизации в Go

Данный блок задач поможет разобраться с механизмами конкурентности в Go, которые необходимы для создания высокопроизводительных систем и надежных API.

---

## 1. Atomic (`sync/atomic`)
*Используется для простых операций над числами без использования тяжелых блокировок.*

*   🟢 **Лёгкая: «Счётчик кликов»**
    *   **Условие:** Создайте 5 горутин.
    *   **Задача:** Каждая должна увеличить общий счётчик на 100, используя `atomic.AddInt64`.
    *   **Результат:** Вывести в консоль итоговое значение (500).

*   🟡 **Средняя: «Глобальный флаг завершения»**
    *   **Условие:** 3 горутины в бесконечном цикле печатают "working...".
    *   **Задача:** Отдельная горутина через 2 секунды должна установить переменную `stop = 1`. Остальные горутины должны проверять состояние флага через `atomic.LoadInt64` и завершаться, если `stop == 1`.

## 🔒 2. Mutex (`sync.Mutex`)
*Обеспечивает исключительный доступ к разделяемым ресурсам (Data Race prevention).*

*   🟢 **Лёгкая: «Безопасное увеличение»**
    *   **Условие:** Запустите 10 горутин.
    *   **Задача:** Каждая горутина должна увеличить обычную переменную-счетчик 1000 раз. Используйте `sync.Mutex` для защиты записи.
    *   **Результат:** Итоговое значение должно быть ровно 10000.

*   🟡 **Средняя: «Банковский счёт»**
    *   **Условие:** Создайте структуру:
        ```go
        type BankAccount struct {
            balance int
            mu      sync.Mutex
        }
        ```
    *   **Задача:** Запустите 5 горутин для метода `Deposit` и 5 для `Withdraw`. Реализуйте проверку: баланс не может стать отрицательным. Вся работа с данными должна быть защищена мьютексом.

---

## 🔁 3. RWMutex (`sync.RWMutex`)
*Оптимизация для систем, где чтение происходит значительно чаще, чем запись.*

*   🟢 **Лёгкая: «Чтение и запись»**
    *   **Задача:** Продемонстрируйте работу `RWMutex`. Создайте 5 горутин, которые читают значение (используя `RLock`), и 1 горутину, которая его периодически изменяет (используя `Lock`).

*   🟡 **Средняя: «Конфигурация сервера»**
    *   **Условие:** Создайте структуру:
        ```go
        type Config struct {
            data map[string]string
            mu   sync.RWMutex
        }
        ```
    *   **Задача:** Реализуйте методы `Get()` (через `RLock`) и `Set()` (через `Lock`). Запустите 10 читающих горутин и 2 пишущих.

## 🗺 4. sync.Map
*Специализированная потокобезопасная карта для специфических сценариев нагрузки.*

*   🟢 **Лёгкая: «Кеш пользователей»**
    *   **Задача:** Добавьте 5 имен пользователей в `sync.Map`. Используя метод `Range`, выведите всех пользователей в консоль.

*   🟡 **Средняя: «Конкурентный логин-кеш»**
    *   **Задача:** 10 горутин одновременно пытаются проверить наличие пользователя или добавить его.
    *   **Инструменты:** Используйте `LoadOrStore`, `Store` и `Load`.
    *   **Ключ:** `username`, **Значение:** количество попыток входа (`login count`).

## ⏱ 5. sync.Once
*Гарантирует выполнение действия строго один раз, что критично для инициализации ресурсов.*

*   🟢 **Лёгкая: «Инициализация конфигурации»**
    *   **Условие:** Функция `initConfig()` печатает "config loaded".
    *   **Задача:** Запустите 10 горутин, каждая из которых вызывает `once.Do(initConfig)`.
    *   **Результат:** Сообщение должно появиться в консоли только 1 раз.

*   🟡 **Средняя: «Ленивая инициализация БД»**
    *   **Условие:** Функция `connectDB()` имитирует подключение (печать + `time.Sleep`).
    *   **Задача:** 5 горутин одновременно запрашивают доступ к БД. Используйте `sync.Once`, чтобы реальное подключение создалось только при первом запросе, а остальные горутины ждали его завершения или использовали готовый объект.
